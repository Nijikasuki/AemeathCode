# 代码审查流程

1. 先搞清这段改动**想解决什么**(读 PR 描述 / commit message / 相关 issue),再看代码。
2. 通读全部改动,建立整体印象,别一上来就抠细节。
3. 按这几类逐一过,每条问题标严重度(🔴 必改 / 🟡 建议 / 🟢 可选):
   - **正确性**:边界条件、错误处理、并发/异步竞态、资源泄漏。
   - **安全**:注入、路径穿越、密钥硬编码、越权。
   - **可维护**:命名、重复、过度复杂、缺测试。
4. 每条问题给出**具体位置 + 为什么是问题 + 怎么改**,不空谈。
5. 结尾一句话总评 + 是否可合并。

原则:对事不对人;能给出修法的问题才算有效反馈;拿不准的标「存疑」而不是当定论。
